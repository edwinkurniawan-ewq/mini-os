TUGAS BESAR MINI OS 
       CPMK : Mahasiswa mampu memahami struktur sistem operasi komputer, proses dan 
       thread, penjadwalan CPU, sinkronisasi, manajemen memori, dan media penyimpanan, 
       serta sistem keamanan dalam desain sistem operasi komputer." 
Ketentuan umum 
    1. Mini-OS harus berupa kernel sederhana yang dapat dijalankan di QEMU atau 
       sejenisnya, bukan hanya aplikasi simulasi yang berjalan di atas Linux atau Windows. 
    
    2. Bebas menggunakan bahasa pemrograman (C, Rust, Assembly, C++, dll) dan diizinkan 
       memanfaatkan bantuan Generative AI dengan catatan harus didokumentasikan. 

    3. Mini-OS wajib memiliki antarmuka konsol/shell internal dengan nama unik dan logo 
       ASCII saat booting. 
    
    4. Penilaian dilakukan melalui demonstrasi sistem secara langsung, pengujian fungsional, 
       dan verifikasi pemahaman.  

    5. Setiap anggota kelompok harus memahami arsitektur dan mekanisme utama Mini-OS 
       serta mampu menjelaskan bagian yang dikembangkan. 
       Ketentuan minimum 


1. Bootstrapping & CLI Kernel  
     • Syarat Minimum: Bootloader memuat kernel ke RAM dan menjalankan 
       antarmuka CLI internal yang menerima input keyboard atau terminal serial 
       QEMU. 
     • Pengujian: OS berhasil booting di QEMU dan mengeksekusi minimal 3 
       perintah CLI buatan kelompok. 

2. Pengelolaan Proses & Thread  
     • Syarat Minimum: Memiliki struktur data pengelolaan thread dan mekanisme 
       pengelolaan status thread. 
     • Pengujian: Menjalankan minimal 2 kernel thread dengan tugas berbeda serta 
       menunjukkan perubahan statusnya (New,Ready, Running, Waiting, dan 
       Terminated) sesuai mekanisme yang diimplementasikan. 

3. Penjadwalan CPU Preemptive  
     • Syarat Minimum: Menerapkan Preemptive Scheduler (seperti Round Robin 
       atau Priority Scheduling). 
     • Pengujian: Scheduler harus nyata mengatur giliran eksekusi CPU via context 
       switching, bukan sekadar simulasi teks printf 

4. Sinkronisasi  
     • Syarat Minimum: Mengimplementasikan mekanisme sinkronisasi berupa 
       mutex atau semaphore untuk melindungi data bersama. 
     • Pengujian: Dua thread melakukan operasi pada shared counter. Bandingkan 
       hasil tanpa sinkronisasi dan dengan sinkronisasi untuk membuktikan 
       terjadinya race condition serta konsistensi data setelah mekanisme 
       pengunci diaktifkan. 

5. Deadlock  
     • Syarat Minimum: Mengimplementasikan mutex atau semaphore serta 
       memahami kondisi terjadinya deadlock. 
     • Pengujian: Mendemonstrasikan dua thread yang menggunakan dua mutex 
       secara berlawanan sehingga keduanya terblokir (deadlock). Mahasiswa 
       kemudian menunjukkan atau menjelaskan solusi, misalnya pengurutan 
       pengambilan mutex untuk mencegah circular wait. 

6. Alokator Memori Dinamis  
     • Syarat Minimum: Mengimplementasikan alokator memori sederhana yang 
       mendukung alokasi dan pelepasan memori. 
     • Pengujian: Menunjukkan perubahan kapasitas memori terpakai dan tersedia, 
       membuktikan memori dapat dilepas, serta menangani kondisi Out of 
       Memory secara aman tanpa menyebabkan kernel crash. 

7. Virtual File System (VFS) Sederhana 
     • Syarat Minimum: Mengimplementasikan sistem berkas sederhana berbasis 
       RAMDisk atau mekanisme setara. 
     • Pengujian: Membuktikan operasi Create, Read, Update, dan Delete (CRUD) 
       pada berkas teks. 

8. Proteksi & Hak Akses 
     • Syarat Minimum: Mengimplementasikan salah satu mekanisme: pemisahan 
       user mode dan kernel mode, atau kontrol hak akses sederhana. 
     • Pengujian: Membuktikan bahwa akses yang diizinkan berhasil dan akses yang 
       tidak diizinkan ditolak. Jika memilih proteksi user mode/kernel mode, 
       mahasiswa harus menunjukkan bahwa akses terlarang ke memori kernel 
       diblokir oleh mekanisme proteks
